# План: «Глаза» — экран-адаптер покерного стола (`pokafer/eyes/`)

Компонент читает состояние покерного стола **с экрана** и собирает Snapshot
для мозга. Правила проекта — DECISIONS.md: цель — наш веб-стол (полигон с
ground truth) и приватные play-money комнаты с согласия участников;
реально-денежные румы, борющиеся с ботами, — вне проекта.

**Граница рантайма:** боевые глаза читают только пиксели экрана (mss) и
действуют реальным вводом (клики, клавиатура). DOM, CDP-скриншоты и
`/debug/state` — только калибровке и автотестам (`pokafer/eyes/truth.py`).

## 0. Что зависит от сайта, а что нет

В разных румах разные шрифты, форматы сумм, раскладки; где-то пишутся
«фолд/колл/чек», где-то нет. Поэтому движок один, а сайт отличается только
**пресетом**, и калибровка под сайт сведена к геометрии:

| Что на экране | Как читаем | Что нужно от нового сайта |
|---|---|---|
| Карты (на сайтах это картинки) | шаблоны, снятые с самого сайта | собрать и один раз подписать 52 карты |
| Числа (стеки, банк, ставки, кнопки) | **готовый распознаватель текста** PP-OCRv5 | только зоны — калибровка под шрифт не нужна |
| Где что лежит | зоны пресета в долях окна | разметить зоны |
| Надписи действий | **необязательные подсказки**: действия выводятся из изменений состояния (карты исчезли, появилась фишка, изменился стек) | ничего |

Почему числа — не шаблоны: рендер текста зависит от шрифта, от субпиксельной
позиции глифа (четыре растра на знак) и от среды (headless против видимого
окна, видеокарта, шрифты машины). Пиксельные шаблоны под шрифт пришлось бы
снимать и отлаживать на каждом сайте — первый заход на этом и увяз.

**Правила зон чисел:**
- зона охватывает **само число** (и знак валюты вплотную), без подписей
  рядом: распознаватель читает всю зону как одну строку. Пустые поля зоны
  перед чтением срезаются (`tighten`) — на плотном кропе модель точнее;
- «элемента нет» (фишка без ставки) отличается от «числа есть» по фону зоны:
  его яркость записана в пресете;
- формат суммы — настройка пресета (`decimal`): разделитель дроби, разделители
  групп, суффиксы «k/m» и «к/м» понимаются; если в зоне несколько чисел,
  берётся самое длинное.

## 1. Реестр и пресет

`data/eyes/sites.toml` — домены → пресеты; файл пресета — `data/eyes/<имя>.toml`:

```toml
[meta]
viewport_ref = [1280, 720]
coords = "ref_px"            # зоны — пиксели референс-вьюпорта (стол не масштабируется)
calibration_id = "…"         # хеш зон и шаблонов карт; читатели сверяют его
seat_layouts = [[…], …]      # какие позиции занимают боты по их числу

[hero]
cards  = [[x, y, w, h], [x, y, w, h]]   # слоты карт
stack  = [x, y, w, h]                  # зона числа
[board]
slots  = [[…] × 5]                     # пять постоянных слотов
[seat.pos_tl]
cards  = [[…], […]]                    # слоты вскрытых карт
backs  = [[…], […]]                    # слоты рубашек
stack  = […]; bet = […]
[pot]   area = […]; amount = […]
[act]   fold = […]; check = […]; …; call_amount = […]

[numbers]                    # зона числа -> яркость фона
"hero.stack" = 26.0
[numbers_format]
decimal = "."
```

Шаблоны — `data/eyes/templates/<пресет>/` (карты, рубашка, пустые слоты).
**Одна калибровка = один `calibration_id`:** читатели отказываются работать,
если id пресета и id шаблонов разные.

## 2. Модули (`pokafer/eyes/`)

| Файл | Роль | Статус |
|---|---|---|
| `capture.py` | захват экрана: `ScreenCapture` (постоянный контекст mss), кадр из файла | ✅ |
| `browser.py` | `TableBrowser`: selenium, точный viewport, headless/видимое окно, `locate_on_screen()`, реальные клики и клавиатура | ✅ |
| `sites.py` | реестр домены→пресеты; `Preset`: зоны, слоты, режим координат | ✅ |
| `slots.py` | перечисление слотов карт пресета | ✅ |
| `cards.py` | `CardReader`: слот → пусто / рубашка / карта / не распознато | ✅ |
| `numbers.py` | `NumberReader`: зона → сумма; `OcrEngine` (PP-OCRv5 через ONNX Runtime); разбор формата | ✅ |
| `perceive.py` | **ядро рантайма**: один кадр → все слоты карт, зоны чисел, сводка по местам | ✅ |
| `loop.py` | цикл зрения: захват кадра → perceive → подписчикам зеркала | ✅ |
| `mirror.py` | «что видят глаза» в разделяемой памяти (seqlock), публикация только при подписчике | ✅ |
| `viewer.py`, `viewer_page.html` | зеркало: отдельный процесс со страницей | ✅ |
| `actuator.py` | действия: фолд/чек-колл/рейз, следующая рука | написан, в бою не обкатан |
| `truth.py` | правда нашего стола для калибровки и тестов (**не рантайм**) | ✅ |
| `tracker.py` | автомат раздачи: улицы, ходы, кто сел/встал; действия — из изменений состояния | 🔜 |
| `snapshot.py` | сборка Snapshot → коннектор мозга | 🔜 |
| `calibrate.py` | разметка зон кликами для чужих сайтов (без DOM) | 🔜 |

Зависимости — отдельные extra, ядро проекта их не тянет:
`pip install -e ".[eyes,ocr]"` → pillow, mss, pynput, selenium; rapidocr,
onnxruntime (распознавание чисел).

## 3. Наш стол под глаза (`pokafer/web/static/`)

Попиксельное сравнение карт требует детерминированной картинки. Все правила
ниже получены из неудач, а не постулированы:

- **Целые позиции.** Середина стола ставится скриптом (`--cx`); CSS-
  центрирование и `transform` для карт не используются. Борд перецентрировался
  с каждой картой и стоял на полупикселях.
- **Борд — пять постоянных слотов; места — боксы фиксированного размера.**
  Табличка места постоянной ширины, строка действия резервируется: подпись
  действия («ставка 9.75») сдвигала карты ботов на десятки пикселей.
- **Лица карт — растровые спрайты** (`scripts/gen_card_sprites.py`).
  Шрифтовый рендер текста зависит от среды (headless против видимого окна:
  сотни отличающихся пикселей на карту), спрайт печатается одинаково везде.
- **Без теней на картах:** тень одной карты ложилась на соседнюю.
- **Фиксированные поля сумм** (стек, кнопка колла, банк): число начинается в
  одной точке и растёт вправо — при любом рендере. Ширина подписи «Банк: »
  различалась между headless и видимым окном на 9 px, и зона резала первую цифру.
- **Кнопки действий фиксированной ширины, без сжатия.** Кнопка «Колл 199.75»
  меняла ширину от надписи и сдвигала «Рейз» и пресеты — клик по запомненной
  зоне попал бы в «Колл».
- **Суммы точные** (до двух знаков): округление теряло четверти блайнда.
- Фолднувшее место приглушает только аватар: общее приглушение до 55% опускало
  контраст текста ниже порога распознавания.
- Страница не прокручивается, высота шапки фиксирована.

**Сервер стола:** сессии именуются клиентом (`?sid=`) — обрыв/F5 возвращают к
тому же столу, а правда читается у своей сессии; после действия героя вид
уходит сразу; клиент блокирует кнопки до ответного вида; итог руки
фиксируется до отправки вида.

## 4. Этапы и статус

| Этап | Содержание | Приёмка | Статус |
|---|---|---|---|
| 0 | Стол под глаза | 1–5 ботов без дефектов, позиции целые | ✅ |
| 1 | Захват + реестр + браузер | кадры идут с экрана и CDP | ✅ |
| 2 | Калибровка нашего стола | ~70 с, самопроверки | ✅ |
| 3 | Карты | ≥ 99% на потоке кадров | ✅ **100%** |
| 4 | Числа | ≥ 98% на потоке кадров | ✅ **100%** |
| 5 | Трекер: улицы, ходы, состав мест | один Snapshot на событие | 🔜 |
| 6 | Snapshot + автотест против правды | расхождений 0 | 🔜 |
| 7 | Бой: глаза → мозг → клик | герой-бот играет только глазами | 🔜 |
| 8 | Чужой сайт: разметка кликами + подпись карт | новый сайт без правки кода | 🔜 |
| — | Зеркало глаз (страница «что видят глаза») | не влияет на конвейер | ✅ |

```bash
pokafer table --port 8011 --bot-think 0.05          # отдельный стол для глаз
python scripts/calibrate_pokafer.py                 # слоты карт + зоны чисел, ~70 с
python scripts/test_card_accuracy.py                # карты, headless (… --screen: пиксели с экрана)
python scripts/test_numbers_accuracy.py             # числа, headless (… --screen)
pokafer eyes-demo --url http://127.0.0.1:8011      # зрение в реальном времени + зеркало
```

**Результаты (2026-11-25, свободная машина):**
- карты: 354/354 за 60 с в headless, 100%; раньше на спрайтовых картах —
  1445/1445 headless и 2346/2346 на экране;
- числа: headless 567/567 и экран 429/429 — 100%, включая 205+156 скрытых
  фишек без единого ложного числа; 16.6 мс на зону (p95 21), 155 мс на кадр.
  Один пресет, снятый в headless, годится и для видимого окна;
- конвейер глаз без зеркала: 131% CPU (≈1.3 ядра из 12), 178 МБ памяти,
  3 кадра/с.

**Выбор распознавателя — по замеру** (18 402 кропа нашего стола: 11 шрифтов,
headless и экран; набор в `data/eyes/eval/`, в git не входит):

| Движок | Числа | Задержка/кроп | Установка |
|---|---|---|---|
| **PP-OCRv5 mobile, ONNX Runtime (RapidOCR 3.10)** | **10 964/10 966 = 99.98%**, весь набор | ~14–17 мс (2 потока, ×3) | ~450 МБ |
| PaddleOCR, та же модель через фреймворк | 1068/1068 (1/10 набора) | ~470 мс | 2.8 ГБ (+torch) |
| Tesseract 5.5 | 672/692 = 97.1% (1/16 набора) | 100–300 мс | 0.5 ГБ |
| EasyOCR | ~34% | ~20 мс | входит в 2.8 ГБ |

На наборе форматов сумм («1.2k», «1,234.56», «12,50 €»; точное совпадение всей
строки): победитель 97–99% (лучше всего при увеличении ×4), Tesseract 82%,
EasyOCR 65%. PP-OCRv6 small так же точна и медленнее; словарь только латиницы
хуже (99.2%). Две ошибки победителя на полном наборе — одиночный «0» прочитан
как «.» на моноширинном шрифте; в рантайге это даёт «числа нет», а не неверное
число. Модели лежат в комплекте rapidocr, без сети.

## 5. Зеркало глаз (страница «что видят глаза»)

На каждый открытый стол — локальная страница с живым кадром: рамки карт,
прочитанные числа и уверенность, время на этап. Для ручной отладки в румах.

- **Изоляция.** Зеркало — отдельный процесс (`pokafer eyes-view`, порт 8020).
  Конвейер пишет состояние в разделяемую память (`mirror.py`, два слота:
  запись никогда не блокирует) и **только пока страницу открыли**: без
  зрителя он ничего не кодирует. Проверено опытом: зеркало убили на 13-й с —
  конвейер отработал без потери кадра.
- **Лёгкость.** Один холст, перерисовка только на новом кадре; зритель
  получает ≤ 12 кадров/с; темп конвейера задаёт `--fps`.
- `pokafer eyes-demo` запускает зеркало сам и печатает адрес; `--no-view` —
  без него. `pokafer stop` останавливает и зеркало.

## 6. Как адаптироваться к чужому руму (процедура)

1. Открыть рум в управляемом браузере глаз (`pokafer eyes-demo --url …`).
2. Разметить зоны: слоты карт, зоны чисел (только число), кнопки действий —
   инструментом разметки кликами (`calibrate.py`, 🔜); реестр: домен → пресет.
3. Карты: собрать изображения с сайта и один раз подписать (🔜 — сборщик
   с кластеризацией).
4. Формат сумм пресета: разделитель дроби, суффиксы.
5. Прогон зеркала глазами; когда появится трекер — его автопроверка.

Числа и надписи действий отдельной настройки не требуют.

## 7. Риски и извлечённые уроки

- **Не возвращаться:** пиксельные шаблоны знаков (4 фазы, калибровка под шрифт
  и среду); ресайз глифов «для нормализации»; побайтовое сравнение кропов в
  пробах (кромка карты зависит от сукна — сравнивать метрикой читателя);
  флаги Chrome не делают рендер текста одинаковым в headless и на экране.
- `ActionChains.move_to_element_with_offset` в Selenium 4 отсчитывает от
  центра элемента: клик «по углу body» попадал на пол-экрана мимо.
- Чужой сайт: анимации и перекрытия → трекер-устойка; смена темы/масштаба →
  пересборка пресета (id калибровки не даст молча смешать старое с новым);
  окно перекрыто другим → захват чужих пикселей, трекер должен отвергать
  кадры по маркеру стола.
- Число по центру широкой зоны рядом с другими подписями читается плохо:
  зона должна начинаться там, где начинаются цифры.
- Соблазн подглядывания: в стол не добавлять скрытых подсказок для глаз —
  иначе автотест теряет смысл. DOM в рантайме глаз запрещён.

Файл фиксирует: что уже сделано на момент старта, что именно строится на

## 0. Что уже сделано (уровень 1, инвентаризация)

- **Ядро** (`pokafer/core/`): движок NLHE 2–6 (сайд-поты, сплиты, инвариант
  чипов), контракт Snapshot/Decision, `evaluate7` + `evaluate7_fast`
  (×11.7, 0 расхождений на 300k рук).
- **Математика эквити** (`core/equity.py`): MC против сэмплеров диапазонов,
  точный ривер (HU), единая семантика win/tie/lose, валидация входов.
- **Абстракция** (`core/abstraction.py`): 169 префлоп-классов, ранжирование
  (артефакт `core/data/preflop_equity.json`, генератор
  `scripts/gen_preflop_equity.py`), аналитический бакет силы (калиброван на
  MC, корреляция 0.81), бакеты стеков, ключи информационных множеств,
  абстрактные ставки + маппинг в легальные.
- **Стратегии** (`brain/strategies/`): equity-машина уровня 1 (MC-эквити vs
  диапазонам, пот-оддсы, SPR, позиция, стеки, статистика соперников,
  изоляция лимперов, пуш коротких стеков, базовый блеф) + калибровочные
  heuristic/micro/fish/random. Диапазоны — `brain/ranges.py`.
- **Инструменты**: bench (инвариант чипов, результаты.jsonl), arena
  (измеренный CI), CLI (status/stop), веб-стол, HTTP-API, терминальное демо.
- **Качество**: 71 тест; арены equity: vs fish +71.7±15.5, vs micro
  +35.7±17.2, vs heuristic +27.3±12.9 (HU 5000); bench 9-max: +135±19.
- **Осознанные упрощения уровня 1** — бэклог в DECISIONS.md §8 (блокеры,
  текстура, ICM, IP/OOP, MDF) — уходит в уровень 2 или остаётся в
  эксплойт-слое.

## 1. Цель уровня 2

Стратегия `gto_blueprint`: равновесная частотная стратегия HU NLHE на
абстракции, обученная MCCFR, с **измеримой** погрешностью (exploitability).
В рантайме — чтение таблицы, ноль вычислений. Дальше она:
- эталон силы для уровней 3+ (эксплойт-слой под слабые популяции);
- главный кандидат в «бот, который всех разносит» (вместе с эксплойт-слоем).

Скоуп: **сначала HU 100bb** (равновесие чётко определено). 6-max —
следующая итерация тем же тренером (external sampling поддерживает N игроков).

## 2. Этап 1 — абстрактное дерево (`pokafer/cfr/tree.py`)

- Состояние = ключ информационного множества из `core/abstraction.py`:
  (улица, класс руки/бакет силы, бакет стека, история абстрактных действий).
- Действия в узле: fold / check / call / bet {0.5, 1.0, 2.0} × банка
  / олл-ин (индексы из `ABSTRACT_BET_FRACTIONS`). Рейзы с улицы переводятся
  в те же фракции от банка после колла.
- Терминальные узлы: ривер/фолд. Выплата = эквити руки против диапазона
  оппонента на вскрытии (evaluate7_fast; кэш по ключу терминала).
- Требования: чистый модуль без стратегии/UI; детерминизм через seed;
  скорость ≥ 50k узлов/с на обход (проверить замером).
- Приёмка: на игрушечном поддереве (2 бакета × 2 сайзинга × 1 улица)
  точный CFR сходится к известному решению аналога Kuhn/Аббатство
  (unit-тест на равновесие малой игры).

## 3. Этап 2 — тренер (`pokafer/cfr/trainer.py` + `scripts/train_blueprint.py`)

- Алгоритм: External-Sampling MCCFR+, чередование игроков, линейное
  усреднение стратегии (вес = номер итерации).
- Таблица: `dict[infoset_key] → regrets[action]` (+ сумма стратегии для
  усреднения); данные — numpy массивы, ключи — строки из abstraction.
- Возобновляемость: чекпоинт каждые N итераций (перезапись + ротация),
  метаданные (итерация, сид, версия абстракции, скорость).
- Прогресс-лог: итерации/с, regret-статистика, контрольный матч против
  прошлого чекпоинта (не падает ли сила).
- Приёмка: 1M итераций HU-абстракции без деградации памяти (утечек),
  воспроизводимость по сиду.

## 4. Этап 3 — артефакт блюпринта

- `data/blueprint/blueprint_v1.npz` (или .json если размер мал) + `meta.json`:
  версия абстракции, число итераций, средняя стратегия.
- Артефакт коммитится; читается только на чтение (DECISIONS §4).
- Переобучение = новая версия файла, старая остаётся.

## 5. Этап 4 — стратегия `gto_blueprint` (`brain/strategies/gto_blueprint.py`)

- Snapshot → infoset_key (через abstraction) → regret matching по таблице →
  распределение по абстрактным действиям → маппинг в легальные размеры
  (`nearest_bet_amount`). Незнакомый ключ → ближайший по бакетам фолбэк.
- Решение — микросекунды, без MC.
- Реестр, тесты: легальность, детерминизм, распределение ≈ таблице.

## 6. Этап 5 — exploitability (научная метрика)

- Точный best response на абстрактном дереве против усреднённой стратегии
  (обход дерева с идеальным знанием нашей стратегии).
- Метрика: «сколько bb/100 выжимает BR из блюпринта» — расстояние до
  равновесия. Цикл: учить → мерить → менять гранулярность → повторять.

## 7. Этап 6 — валидация и интеграция

- Арены: gto_blueprint vs equity / fish / micro / heuristic (HU 20k+).
- Критерий успеха: блюпринт бьёт equity-машину HU и exploitability
  стабильно снижается с итерациями.
- Интеграция: веб-стол/демо (чип бота «gto»), `pokafer bench`.

## 8. Что нужно от исследователя

- **VPS: `nproc` и RAM** — от этого зависит гранулярность абстракции
  (число бакетов силы) и план ночных прогонов. До получения — этапы 1–2
  отлаживаются на этой машине на грубой абстракции.

## 9. Критерии приёмки уровня 2 (summary)

1. `pokafer arena --a gto_blueprint --b equity` — уверенный плюс.
2. Exploitability падает монотонно с итерациями и измеряется.
3. Решение по Snapshot — без MC, < 1 мс.
4. Все тесты зелёные; блюпринт интегрирован в стол/бенчмарк.

## 10. Риски

- Грубая абстракция → слабый блюпринт: лечится гранулярностью (нужен VPS).
- Память под таблицы: при переполнении — сжатие/срез бакетов, npz-форматы.
- Качество терминальных выплат: кэш эквити по терминальным ключам,
  проверка выборкой.
- 6-max: множество равновесий — для начала фиксируем одно (усреднение CFR).

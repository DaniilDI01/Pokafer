# Pokafer: архитектура и как всё работает

Проект: покерный ИИ для исследований покерной математики и поведения людей.
Ядро идеи — **один контракт данных (Snapshot JSON)** между всеми частями:
движок, мозг, интерфейсы и инструменты обкатки говорят на одном языке,
поэтому всё стыкуется без переделок.

```
Источники состояния                    МОЗГ                     Потребители
─────────────────                 ──────────────              ──────────────
движок раздачи ─→ Snapshot JSON → валидация → легальные       → Decision JSON
веб-стол (живая игра) ─┘            действия → стратегия        → панель кнопок
исторические JSONL ─→ replay ─┘     (смешанная) → сэмпл        → графики/логи
                                    + память об оппонентах      → анализ людей
```

## Карта репозитория

```
Pokafer/
├── configs/
│   └── benchmark.py          # конфиг обкатки: место -> стратегия, hands, seed
├── pokafer/                  # библиотека (всё главное здесь)
│   ├── core/                 # «физика» покера — не знает ни про мозг, ни про UI
│   │   ├── schema.py         #   Snapshot / Decision / ActionRecord / SeatState
│   │   ├── cards.py          #   карты (индекс = rank*4+масть), evaluate7, имена рук
│   │   ├── legal.py          #   легальные действия + меню сайзингов
│   │   └── engine.py         #   HandEngine: раздача 2–6 игроков, сайд-поты
│   ├── brain/                # принятие решений — не знает про UI
│   │   ├── api.py            #   Brain: Snapshot -> Decision (пайплайн)
│   │   ├── strategies/       #   реестр стратегий (см. ниже)
│   │   ├── memory.py         #   память об оппонентах (VPIP/PFR/AF)
│   │   └── service.py        #   HTTP-API (FastAPI): POST /v1/decide
│   ├── web/                  # веб-стол
│   │   ├── table_server.py   #   WebSocket-сервер: сессия стола, боты, протокол
│   │   └── static/           #   браузерный клиент без сборки (html/js/css)
│   ├── benchmark.py          # универсальная проверялка стратегий + инвариант чипов
│   ├── analysis/             # поведенческая статистика по снапшотам
│   ├── adapters/             # источники данных: replay JSONL, (заготовка PokerNow)
│   └── cli.py                # единая команда `pokafer` (подкоманды -> скрипты)
├── scripts/                  # тонкие лаунчеры (демо, серверы, арена, бенчмарк)
├── tests/                    # 39 тестов: контракты, движок, мозг, WS-протокол
└── data/
    ├── raw/                  # сырые экспорты румов (будущий парсер)
    ├── snapshots/            # JSONL-истории раздач (пишет demo, читает replay)
    └── logs/                 # логи бенчмарка, results.jsonl, отчёты, crash-дампы
```

## 1. core/schema.py — язык проекта

**Snapshot** — полное состояние раздачи С ТОЧКИ ЗРЕНИЯ одного игрока
(`actor_seat`): его карты (`hole_cards` только у `is_hero=True`), борд, банк,
стеки/вложения всех мест, вся история действий. Скрытая информация не
протекает: `engine.snapshot_for(seat)` показывает карты только этого места.

**Decision** — ответ мозга: действие (`fold/check/call/bet/raise`),
сумма «до», **distribution** — смешанная стратегия (вероятности действий),
пояснение и время.

Ключ действия — единый формат: `fold`, `check`, `call:2`, `bet:6`, `raise:12`.

## 2. core/cards.py — карты и комбинации

Карта = индекс 0..51 (`rank*4 + suit`), ранги 2..A. `evaluate7()` выбирает
лучшую пятёрку из 5–7 карт и возвращает сравнимый кортеж
`(категория, киккеры...)`; `hand_name_ru()` — «две пары: J и 3».

## 3. core/legal.py — что можно делать

Из Snapshot выводит: фолд (если есть ставка), чек/колл (колл укорачивается
до олл-ина), и **меню сайзингов** ставки/рейза: мин-рейз, ~½/¾/банк,
«рейз банком», олл-ин (всегда присутствует — отдельным элементом).
Мозг выбирает ТОЛЬКО из этого меню — нелегальных действий не бывает.

## 4. core/engine.py — движок раздачи (2–6 игроков)

`HandEngine(seat_stacks, names, button_seat, ...)`:
- раздаёт карты, ставит блайнды (HU: кнопка = SB, ходит первой префлоп;
  3+ — первый после BB), ведёт круги ставок по улицам;
- раунд закрыт, когда все не-олл-ин активные походили и ставки равны;
  повышение сбрасывает счётчик «кто уже ответил»;
- олл-ины: недокрытая часть последней ставки ВОЗВРАЩАЕТСЯ
  (`_refund_uncalled`), банк делится на слои (`_side_pots`), сплиты —
  целыми центами, остаток цента первому победителю;
- итог (`result`): победители, банки по слоям, выигрыши, вскрывшиеся карты;
  `bet_street/invested` обнуляются (иначе двойной счёт — ловится
  инвариантом бенчмарка).

## 5. brain — как принимается решение

`Brain.decide(snap)` (pokafer/brain/api.py):
1. `legal_actions(snap)` — меню;
2. `strategy.distribution(snap, legal)` — **смешанная стратегия**:
   вероятности по действиям (здесь живёт непредсказуемость и блеф);
3. сэмплирование действия из распределения;
4. `Decision` + пояснение (+ профили оппонентов из памяти, если есть).

Стратегии — подключаемые модули (pokafer/brain/strategies/):
- `base.Strategy` — интерфейс: `distribution()` возвращает dict;
- `random` — равномерно (калибровка);
- `heuristic` — недо-GTO: сила руки (формула Чена префлоп / категория+дро
  постфлоп), пот-оддсы, рандомизированные блефы. Все пороги — в словаре
  `PARAMS`;
- `micro` — наследник heuristic: только переопределяет PARAMS (блеф почти
  выключен, тонкий велью, крупнее сайзинги) — эксплойт под микролимиты;
- `fish` — синтетическая «рыба» (лузово-пассивная модель популяции NL2–10).

Реестр: `strategies/__init__.py` (`register/available/get`). **Добавить
стратегию = один файл с классом + одна строка регистрации** — она сразу
доступна в CLI, столе, бенчмарке.

`memory.py` — накапливает снапшоты раздач и считает профили (VPIP/PFR/AF/
фолд-vs-бет) через `analysis/opponent_stats.py` — фундамент будущего слоя
эксплойта под конкретного соперника.

## 6. Интерфейсы

**HTTP-API мозга** (`brain/service.py`): stateless, `POST /v1/decide`
принимает снапшот, возвращает Decision; `/v1/schema` — JSON-схема;
`/v1/strategies` — список. Доля миллисекунды на решение.

**Веб-стол** (`web/table_server.py` + `static/`): человек (место 1) против
до 5 ботов, у каждого своя стратегия (меняется на лету сообщением
`configure`). Протокол WebSocket: сервер шлёт `view` (вид стола с
перспективы героя), `bot` (ход бота с его распределением), `result`
(итог; карты шоудауна не прячутся до следующей руки); клиент — `action`,
`new_hand`, `configure`, `hint`. Боты ходят с паузой 0.5 с; следующая
рука — только по кнопке. Клиент — vanilla JS без сборки: стол, слайдер
рейза с пресетами, лог с распределениями, кнопки всегда видны (недоступные
— серые).

**CLI** (`cli.py`): `pokafer` без аргументов — список команд; каждая
подкоманда пробрасывает флаги в свой скрипт (справка: `pokafer X -h`);
`pokafer status` — что запущено, стратегии, последние прогоны.

## 7. Инструменты обкатки

**benchmark** (`pokafer/benchmark.py`, конфиг `configs/benchmark.py`):
рассадка «место → стратегия» (кнопка равномерно по кругу — позиционного
смещения нет), свежие стеки на каждую раздачу, тысячи раздач быстро
(~440 рук/с на 9-max), итог — bb/100 на место ± 95% CI и HTML-отчёт с
графиком суммарного банка каждой стратегии.

Главное — **инвариант целостности**: после КАЖДОГО действия проверяется,
что Σ(стеки+вложения) не изменилась и стеки не отрицательны. Нарушение —
аварийный дамп раздачи (действия + сид колоды) в `data/logs/` и останов.
Именно он поймал два реальных бага движка (двойной счёт invested после
раздачи; утечку цента в сплит-потах 7/3).

История прогонов копится в `data/logs/results.jsonl` (для статьи).

**arena** — дуэль 1-на-1 двух стратегий (bb/100, CI).
**replay** — прогон мозга по историческим JSONL-снапшотам + профили игроков.

## 8. Как сделать типовые вещи

Добавить стратегию:
1. файл `pokafer/brain/strategies/my.py` с классом (наследуй `HeuristicStrategy`
   и переопредели `PARAMS`, либо пиши свой `distribution`);
2. зарегистрировать в `strategies/__init__.py`;
3. `pytest`; использовать: `pokafer demo --strategy my`, вписать в
   `configs/benchmark.py` или чип бота на столе.

Обкатать: отредактировать `configs/benchmark.py` → `pokafer bench`.
Отчёт: `data/logs/benchmark_*.html` (график + таблица).

## 9. Честные ограничения и долги

- дубли в UI-слое: перевод действий (`human_action` в demo_cli ≈
  `_ru_action` в table_server), константы HERO/NAMES/STREET_RU — при
  правках трогать оба места;
- подсказка комбинации в браузере (JS) грубее, чем `evaluate7` в CLI;
- анте не реализовано (поле в схеме есть);
- мозги ботов на веб-столе без памяти об оппонентах (в CLI — есть);
- парсер PokerNow — заготовка, ждёт реальный экспорт в `data/raw/`.

## 10. Тесты

`pytest -q` — 39 штук: JSON-контракт туда-обратно, легальность действий,
сохранение чипов (включая стресс 300 раздач до цента и сайд-поты),
CFR-уровень мозга, WebSocket-протокол стола, инварианты бенчмарка.

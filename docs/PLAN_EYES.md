# План: «Глаза» — адаптер окна покерного стола (`pokafer/eyes/`)

Устройство глаз и порядок адаптации к другому руму — [EYES_GUIDE.md](EYES_GUIDE.md).
Здесь — этапы, измерения и уроки.

Компонент читает состояние покерного стола по пикселям его окна — кадр
отдаёт браузер — собирает Snapshot для мозга и в бою ведёт героя: мозг
решает, актатор кликает. Правила проекта —
DECISIONS.md: цель — наш веб-стол (полигон с
ground truth) и приватные play-money комнаты с согласия участников;
реально-денежные румы, борющиеся с ботами, — вне проекта.

**Граница рантайма:** боевые глаза читают только пиксели кадра и действуют
реальным вводом (клики, клавиатура). Кадр отдаёт сам браузер — окно стола
можно таскать, перекрывать другими окнами и уводить за край экрана: глаза
читают страницу, а не монитор. DOM, команды браузера и `/debug/state` —
только калибровке и автотестам (`pokafer/eyes/truth.py`). Съём с монитора
(mss) остался запасным путём для страниц вне нашего браузера и проверкой
«как на экране» (`--screen`).

## 0. Что зависит от сайта, а что нет

В разных румах разные шрифты, форматы сумм, раскладки; где-то пишутся
«фолд/колл/чек», где-то нет. Поэтому движок один, а сайт отличается только
**пресетом**, и калибровка под сайт сведена к геометрии:

| Что на экране | Как читаем | Что нужно от нового сайта |
|---|---|---|
| Карты (на сайтах это картинки) | шаблоны, снятые с самого сайта | собрать и один раз подписать 52 карты |
| Числа (стеки, банк, ставки, кнопки) | **готовый распознаватель текста** PP-OCRv5 | только зоны — калибровка под шрифт не нужна |
| Где что лежит | зоны пресета в долях окна | разметить зоны |
| Надписи действий | **необязательные подсказки**: действия выводятся из изменений состояния (карты исчезли, появилась фишка, изменился стек) | ничего |

Почему числа — не шаблоны: рендер текста зависит от шрифта, от субпиксельной
позиции глифа (четыре растра на знак) и от среды (headless против видимого
окна, видеокарта, шрифты машины). Пиксельные шаблоны под шрифт пришлось бы
снимать и отлаживать на каждом сайте — первый заход на этом и увяз.

**Правила зон чисел:**
- зона охватывает **само число** (и знак валюты вплотную), без подписей
  рядом: распознаватель читает всю зону как одну строку. Пустые поля зоны
  перед чтением срезаются (`tighten`) — на плотном кропе модель точнее;
- «элемента нет» (фишка без ставки) отличается от «числа есть» по фону зоны:
  его яркость записана в пресете;
- формат суммы — настройка пресета (`decimal`): разделитель дроби, разделители
  групп, суффиксы «k/m» и «к/м» понимаются; если в зоне несколько чисел,
  берётся самое длинное.

## 1. Реестр и пресет

`data/eyes/sites.toml` — домены → пресеты; файл пресета — `data/eyes/<имя>.toml`:

```toml
[meta]
viewport_ref = [1280, 720]
coords = "ref_px"            # зоны — пиксели референс-вьюпорта (стол не масштабируется)
calibration_id = "…"         # хеш зон и шаблонов карт; читатели сверяют его
seat_layouts = [[…], …]      # какие позиции занимают боты по их числу

[hero]
cards  = [[x, y, w, h], [x, y, w, h]]   # слоты карт
stack  = [x, y, w, h]                  # зона числа
[board]
slots  = [[…] × 5]                     # пять постоянных слотов
[seat.pos_tl]
cards  = [[…], […]]                    # слоты вскрытых карт
backs  = [[…], […]]                    # слоты рубашек
stack  = […]; bet = […]
[table] seat_order = ["hero", …]      # места по часовой стрелке от героя (трекеру); sb, bb
[pot]   area = […]; amount = […]
[act]   fold = […]; check = […]; …; call_amount = […]
park   = [x, y, w, h]                    # пустая точка: актатор уводит сюда курсор после клика
[flags] "hero.turn" = […]                # индикаторы: ход, дилер, «рука окончена» — по два эталона

[numbers]                    # зона числа -> яркость фона
"hero.stack" = 26.0
[numbers_format]
decimal = "."
```

Шаблоны — `data/eyes/templates/<пресет>/` (карты, рубашка, пустые слоты,
эталоны индикаторов `flag_*_on/off.png`).
**Одна калибровка = один `calibration_id`:** читатели отказываются работать,
если id пресета и id шаблонов разные.

Что означает каждая группа полей и как по ним читаются слоты и числа —
[EYES_GUIDE.md](EYES_GUIDE.md) §6.

| `actuator.py` | действия: фолд/чек-колл/рейз (сумма — вводом в поле, олл-ин — пресетом), следующая рука; курсор уходит с кнопки | ✅ обкатан в бою |
| `truth.py` | правда нашего стола для калибровки и тестов (**не рантайм**): замороженные и живые кадры, индикаторы, история движка | ✅ |
| `level.py` | кадр → уровень: сырые чтения → состояние стола; недостоверное — не информация | ✅ |
| `history.py` | действия между двумя состояниями — поиск по правилам покера (`legal_actions`); свидетели | ✅ |
| `tracker.py` | автомат раздачи: подтверждение двумя кадрами, улицы, ходы, состав мест, Snapshot для мозга, события; `serial` — номер состояния | ✅ |
| `pilot.py` | бой: одно решение на состояние, мозг → актатор, проверка клика по истории, повторы, стоп | ✅ |
| `report.py` | строки терминала: события трекера, ходы пилота, итог боя | ✅ |
| `table_setup.py` | подготовка нашего стола до цикла (DOM): соединение, посадка ботов | ✅ |
| `calibrate.py` | разметка зон кликами для чужих сайтов (без DOM) | 🔜 |

Зависимости — отдельные extra, ядро проекта их не тянет:
`pip install -e ".[eyes,ocr]"` → pillow, mss, pynput, selenium; rapidocr,
onnxruntime (распознавание чисел).

## 3. Наш стол под глаза (`pokafer/web/static/`)

Попиксельное сравнение карт требует детерминированной картинки. Все правила
ниже получены из неудач, а не постулированы:

- **Целые позиции.** Середина стола ставится скриптом (`--cx`); CSS-
  центрирование и `transform` для карт не используются. Борд перецентрировался
  с каждой картой и стоял на полупикселях.
- **Борд — пять постоянных слотов; места — боксы фиксированного размера.**
  Табличка места постоянной ширины, строка действия резервируется: подпись
  действия («ставка 9.75») сдвигала карты ботов на десятки пикселей.
- **Лица карт — растровые спрайты** (`scripts/gen_card_sprites.py`).
  Шрифтовый рендер текста зависит от среды (headless против видимого окна:
  сотни отличающихся пикселей на карту), спрайт печатается одинаково везде.
- **Без теней на картах:** тень одной карты ложилась на соседнюю.
- **Фиксированные поля сумм** (стек, кнопка колла, банк): число начинается в
  одной точке и растёт вправо — при любом рендере. Ширина подписи «Банк: »
  различалась между headless и видимым окном на 9 px, и зона резала первую цифру.
- **Кнопки действий фиксированной ширины, без сжатия.** Кнопка «Колл 199.75»
  меняла ширину от надписи и сдвигала «Рейз» и пресеты — клик по запомненной
  зоне попал бы в «Колл».
- **Суммы точные** (до двух знаков): округление теряло четверти блайнда.
- Фолднувшее место приглушает только аватар: общее приглушение до 55% опускало
  контраст текста ниже порога распознавания.
- Страница не прокручивается, высота шапки фиксирована.

**Сервер стола:** сессии именуются клиентом (`?sid=`) — обрыв/F5 возвращают к
тому же столу, а правда читается у своей сессии; после действия героя вид
уходит сразу; клиент блокирует кнопки до ответного вида; итог руки
фиксируется до отправки вида.

## 4. Этапы и статус

| Этап | Содержание | Приёмка | Статус |
|---|---|---|---|
| 0 | Стол под глаза | 1–5 ботов без дефектов, позиции целые | ✅ |
| 1 | Захват + реестр + браузер | кадры идут от браузера (и с монитора — запасной путь) | ✅ |
| 2 | Калибровка нашего стола | ~70 с, самопроверки | ✅ |
| 3 | Карты | ≥ 99% на потоке кадров | ✅ **100%** |
| 4 | Числа | ≥ 98% на потоке кадров | ✅ **100%** |
| 5 | Индикаторы: чей ход, дилер, «рука окончена» | ни одной ошибки, включая ходы ботов | ✅ **100%** (headless и видимое окно) |
| 6 | Трекер: улицы, ходы, состав мест, Snapshot | срез против движка: уровень — расхождений 0, история — ни одного выдуманного действия | ✅ **317/317 и 412/412**; быстрый стол — помеченные пропуски |
| 7 | Бой: глаза → мозг → клик | герой-бот играет только глазами; срез, меню и каждый клик — против движка | ✅ **обычный темп: уровень и история 100%, клики как решено 100%; быстрый стол — без единого «иначе»** |
| 8 | Чужой сайт: разметка кликами + подпись карт | новый сайт без правки кода | 🔜 |
| — | Зеркало глаз (страница «что видят глаза») | не влияет на конвейер | ✅ |
| — | Свободное окно: таскать, перекрывать, сворачивать | три состояния окна, реальные клики | ✅ |

python scripts/test_tracker_accuracy.py            # трекер: срез против движка (… --headed; --url …:8012)

| Движок | Числа | Задержка/кроп | Установка |
|---|---|---|---|
| **PP-OCRv5 mobile, ONNX Runtime (RapidOCR 3.10)** | **10 964/10 966 = 99.98%**, весь набор | ~14–17 мс (2 потока, ×3) | ~450 МБ |
| PaddleOCR, та же модель через фреймворк | 1068/1068 (1/10 набора) | ~470 мс | 2.8 ГБ (+torch) |
| Tesseract 5.5 | 672/692 = 97.1% (1/16 набора) | 100–300 мс | 0.5 ГБ |
| EasyOCR | ~34% | ~20 мс | входит в 2.8 ГБ |

На наборе форматов сумм («1.2k», «1,234.56», «12,50 €»; точное совпадение всей
строки): победитель 97–99% (лучше всего при увеличении ×4), Tesseract 82%,
EasyOCR 65%. PP-OCRv6 small так же точна и медленнее; словарь только латиницы
хуже (99.2%). Две ошибки победителя на полном наборе — одиночный «0» прочитан
как «.» на моноширинном шрифте; в рантайге это даёт «числа нет», а не неверное
число. Модели лежат в комплекте rapidocr, без сети.

## 5. Зеркало глаз (страница «что видят глаза»)

На каждый открытый стол — локальная страница с живым кадром: рамки карт,
прочитанные числа и уверенность, время на этап. Для ручной отладки в румах.

- **Открывается сама.** `pokafer eyes-demo` поднимает зеркало, печатает адрес
  и открывает страницу в браузере по умолчанию (нужен рабочий стол);
  `--no-open` — не открывать. Страница может лежать как угодно, хоть поверх
  окна стола: кадры отдаёт браузер, а не монитор.
- **Изоляция.** Зеркало — отдельный процесс (`pokafer eyes-view`, порт 8020).
  Конвейер пишет состояние в разделяемую память (`mirror.py`, два слота:
  запись никогда не блокирует) и **только пока страницу открыли**: без
  зрителя он ничего не кодирует. Проверено опытом: зеркало убили на 13-й с —
  конвейер отработал без потери кадра.
- **Лёгкость.** Один холст, перерисовка только на новом кадре; зритель
  получает ≤ 12 кадров/с; темп конвейера задаёт `--fps`. Страница читается
  с диска на каждый запрос: правки видны после F5, без перезапуска.
- `--no-view` — без зеркала. `pokafer stop` останавливает и зеркало.

## 6. Окно браузера свободно

Требование исследователя: глаза не должны зависеть от того, где стоит окно
стола. Что проверено опытами на Chrome 139 (MATE/X11) и приёмкой
`test_window_states.py`:

| Что делают с окном | Кадры | Реальные клики |
|---|---|---|
| таскают, перекрывают другими окнами | идут; окно не поднимается наверх | принимаются |
| уводят за край экрана | идут с той же скоростью | — |
| сворачивают | не идут: скрытую страницу браузер не рисует; глаза разворачивают окно | — |
| `--headless` (окна нет) | идут | принимаются |

- **Кадр берётся напрямую у браузера** (`Page.captureScreenshot`), а не
  командой снимка WebDriver: та поднимает перекрытое окно наверх, разворачивает
  свёрнутое и вдвое медленнее (125 против ~60 мс), пиксели те же.
- **Свёрнутое окно.** Запрос кадра скрытой страницы повисает навсегда.
  Поэтому глаза заранее спрашивают страницу, видна ли она, и со свёрнутым
  окном бросают `WindowHidden`: цикл пропускает кадр, разворачивает окно и
  пишет об этом. Свернуть окно «по-настоящему» нельзя; чтобы окна не было
  вовсе — `--headless`. Приёмка проверяет и это: кадр со свёрнутым окном не
  запрашивается.
- **Курсор после клика.** Оставленный на кнопке, он держит подсветку
  наведения: фон зоны числа меняется, и глаза решают «элемента нет» (на
  нашем столе сумма колла читалась как «пусто» в каждом втором кадре).
  Актатор уводит курсор в пустую точку пресета (`act.park`).
- **Съём с монитора** — запасной путь (`--screen` в тестах, `ScreenCapture`
  для страниц вне нашего браузера): окно должно быть видно целиком и ничем не
  перекрыто, иначе в кадре чужие пиксели. С монитора кадр совпадает с кадром
  браузера во всём, кроме 6 верхних строк (там рамка окна).

## 7. Как адаптироваться к чужому руму (процедура)

Подробный порядок — с командами, снимком первого взгляда и оговорками о
том, что ещё не сделано, — в [EYES_GUIDE.md](EYES_GUIDE.md) §8; здесь кратко.

1. Открыть рум в управляемом браузере глаз (`pokafer eyes-demo --url …`).
2. Разметить зоны: слоты карт, зоны чисел (только число), кнопки действий —
   инструментом разметки кликами (`calibrate.py`, 🔜); реестр: домен → пресет.
3. Карты: собрать изображения с сайта и один раз подписать (🔜 — сборщик
   с кластеризацией).
4. Формат сумм пресета: разделитель дроби, суффиксы.
5. Прогон зеркала глазами; автопроверка трекера (`scripts/test_tracker_accuracy.py`)
   возможна только там, где есть правда (наш стол).

Числа и надписи действий отдельной настройки не требуют.

Граница — DECISIONS.md: свой стол и приватные play-money комнаты с согласия
участников; румы на реальные деньги, борющиеся с ботами, — вне проекта.

**Первый шаг к чужому руму без самого рума — тема по скриншотам** (идея
исследователя). Присылаются 5–10 снимков настоящего рума (лучше разные
улицы, ставки, вскрытие), по ним делается тема нашего веб-стола: палитра,
карты, шрифты и посадка чисел, раскладка мест. Глаза калибруются и
проверяются на ней — с правдой и без риска для чьего-либо аккаунта. Для
этого нужна параметризация темы стола (набор карт + палитра + раскладка) и
разметка зон на произвольной раскладке. На настоящем руме распознаватель
чисел ещё не проверялся: он показан на 11 шрифтах нашего стола.

## 8. Риски и извлечённые уроки

- **Не возвращаться:** пиксельные шаблоны знаков (4 фазы, калибровка под шрифт
  и среду); ресайз глифов «для нормализации»; побайтовое сравнение кропов в
  пробах (кромка карты зависит от сукна — сравнивать метрикой читателя);
  флаги Chrome не делают рендер текста одинаковым в headless и на экране;
  кадр с монитора как основной путь (окно сдвинули или перекрыли — в кадре
  чужие пиксели, а глаза выдают их за уверенные показания) и команда снимка
  WebDriver (поднимает и разворачивает окно).
- `ActionChains.move_to_element_with_offset` в Selenium 4 отсчитывает от
  центра элемента: клик «по углу body» попадал на пол-экрана мимо.
- Чужой сайт: анимации и перекрытия → трекер-устойка; смена темы/масштаба →
  пересборка пресета (id калибровки не даст молча смешать старое с новым);
  кнопка под курсором подсвечена — её число не читается (курсор уходит с
  кнопки после клика, а в чужом руме подсветку наведения надо проверить).
- Стенд правды: «действие принято» — это изменение банка и денег на столе, а
  не только номер руки, борд и номер ходящего: герой чекает, бот за ним
  ставит — ход возвращается к герою на той же улице, и грубый ключ этого не
  замечал.
- «Чьё это окно» — по профилю Chrome (он вписан в класс окна), а не по
  заголовку страницы: у того же стола в другом демо заголовок одинаков, и
  проверка «чужое окно осталось поверх» приняла его за своё.
- Число по центру широкой зоны рядом с другими подписями читается плохо:
  зона должна начинаться там, где начинаются цифры.
- Соблазн подглядывания: в стол не добавлять скрытых подсказок для глаз —
  иначе автотест теряет смысл. DOM в рантайме глаз запрещён.
- Значок дилера — диск, не буква: глиф текста в headless и в видимом окне
  разный (приёмка индикаторов ловила: 0/103). Всё, что глаза сравнивают по
  пикселям, — геометрия и цвет.
- Самопроверка калибровки обязана ставить страницу в ВОЗМОЖНЫЕ состояния:
  включённая подсветка хода у сбросившего места — состояние, которого в игре
  не бывает; читатель правильно отвечал «неизвестно», а проверка считала это
  ошибкой.
- Стенд правды на живой игре: кадр сопоставляется правде, только если
  состояние не менялось ДО и ПОСЛЕ съёмки, а страница уже показывает то же,
  что сервер (`synced_truth`); иначе пара «кадр ↔ правда» лжёт.
- Движок стола тасует колоду без зерна: тесты «плавали» от запуска к запуску.
  Зерно сессии теперь задаёт колоду каждой руки.
- Стенд останавливается на JS-ошибке страницы сразу: иначе клики теряются
  молча, и это выглядит как ошибка глаз или трекера.

Уроки боя (этап 7):

- Движение курсора в Selenium по умолчанию длится 250 мс: клик с парковкой
  курсора стоил полсекунды, рейз — секунду, и на быстром столе цикл боя
  выдавал 2,2 кадра/с. Мгновенное движение (`MOVE_MS = 0`) вернуло 7.
- Тройной клик не выделяет прежнее значение поля надёжно: «рейз до 5» вышел
  «до 45» (ввод дописался). Ctrl+A после клика в поле — надёжно.
- Судья приёмки обязан судить состояние трекера в тот кадр, когда оно
  принято, и после чтения правды у движка сверять, что стол не ушёл. Иначе
  состояние сравнивалось с уже изменившимся столом — ложные «выдумано».
- Зона стека с запасом 8 px за краем таблички на вскрытии захватывала карту
  места, в остальное время — сукно. Одиночный «0» стека олл-ина в широкой
  зоне модель читала как «。」: 749 кадров из 1056 недостоверны, пилот
  остановил бой. Зона теперь кончается краем таблички; число, не вышедшее с
  первого раза, перечитывается вплотную к явным знакам. Нашлось только в бою
  со случайной стратегией — эвристические боты олл-ин почти не ставят.
- `serial` трекера расти только на новом состоянии: иначе «одно решение на
  состояние» не работает (то же состояние подтверждалось каждые два кадра).
- Округление до копейки в `legal_actions` на полкопейки плавало (60.945 —
  то 60.94, то 60.95, смотря как суммировали банк): движок и трекер (банк с
  экрана строкой) разошлись на цент в меню. Округление с эпсилоном.
- Приёмка без критерия «недостоверных кадров» пропускала бой, в котором
  глаза не видели стол: проходила формально по пустому множеству. Теперь
  недостоверных кадров должно быть не больше 2%.

# Решения проекта (зафиксировано)

Этот файл — «конституция» проекта: ключевые решения и требования, согласованные
с исследователем. Менять задним числом нельзя — только дополнять новыми
решениями с датой.

## 1. Цель проекта

**Супер-сильный мозг** — стратегия уровня сильного регуляра, умеющая подстраиваться
и под слабых соперников (низкие NL). Ближайшая цель — «бот, который всех разносит».

Порядок исследования и написание статьи определяет исследователь; проект не
двигает их сам — только обеспечивает сильный эталон и инструменты замера.

## 2. Лестница стратегий

| Уровень | Что это | Статус |
|---|---|---|
| Калибровочные эвристики (heuristic/micro/fish) | модели-мишени и бейзлайны, не «настоящая сила» | ✅ есть |
| **Уровень 1: equity-машина** | решения из вычисленных вероятностей: MC-эквити vs диапазону, пот-оддсы, EV | ✅ есть |
| **Уровень 2: MCCFR-блюпринт** | обученное равновесие упрощённой игры (CFR), таблица регретов | следующий этап, фундамент готов |
| **Уровень 3: эксплойт-слой** | подстройка блюпринта под конкретных соперников (статистика/клоны) | после уровня 2 |

**Нейросеть — не самоцель.** Табличный CFR + эксплойт-эвристики на нашем
масштабе, вероятно, сильнее маленькой NN. NN рассматриваем только если она
решает конкретную задачу таблицы: интерполяция между бакетами абстракции,
модель оппонента по последовательности действий, или формальное требование
руководителя (тогда — дёшево: дистилляция блюпринта в сеть). Решение —
после того, как увидим, где блюпринт реально проваливается.

## 3. Схема GTO — гибрид, без изобретения решённого

- **Префлоп**: готовые математически выведенные чарты/таблицы (задача решена до нас).
  Артефакт — локальный файл в репо, сгенерированный нашим скриптом.
- **Постфлоп**: свой MCCFR-тренер (Pluribus-рецепт) на абстракции.
- **TexasSolver** (open source, локально) — офлайн-«оракул»: меряет погрешность
  нашего блюпринта. В принятии решений НЕ участвует.
- **Slumbot** — только внешний тест силы через API, опционально, к мозгу не относится.

Честные ограничения блюпринта: он — равновесие **упрощённой** игры (руки-группы,
3–4 размера ставок, стеки-диапазоны) на конечном числе итераций. Измеримая
погрешность (exploitability) — часть научного результата. Точное решение реально
на ривере (маленькое дерево) и в малых играх.

## 4. Правило локальности

**Мозг работает без сети. Ноль обращений онлайн в принятии решений.**
- таблицы (префлоп, блюпринт) — генерируемые артефакты внутри репозитория;
- все вычисления — локальный CPU;
- любые внешние сервисы — только офлайн-проверки/замеры, никогда не часть мозга.

## 5. Модульность (главная фича проекта)

```
Платформа/парсер (адаптер) → Snapshot JSON → МОЗГ (JSON в → JSON из) → Decision JSON
        ↑ отдельный модуль              ↑ опционально: profiles            ↓
   Observer (сбор статистики)      {vpip, pfr, fold_vs_bet...}         потребители
```

- **Мозг — чистая функция**: ничего не парсит, не хранит, не пишет; состояние
  приходит в аргументах. Стратегия получает профили аргументом, не хранит их.
- **Парсер будущего рума** — отдельный модуль в `adapters/`, не привязан к
  стратегии, числу игроков за столом и платформе. Конвертирует формат → Snapshot.
- **Наблюдение за столом** — платформа решает сама: собирать ли статистику и
  кормить ли ею мозг.
- **Число игроков** берётся из Snapshot (2–6), стратегии не знают про платформу.
- Стратегия — самодостаточный файл: `distribution(snap, legal, profiles)` +
  PARAMS-словарь; без глобальных синглтонов и runtime-кэшей.

## 6. Требования к префлоп-логике

Префлоп обязан учитывать (все данные уже в Snapshot):
- **свой стек в блайндах** и **стеки соперников** (эффективный стек);
- **позицию относительно баттона** (диапазоны открытия, защита блайндов против стила);
- **соперников, сбросивших карты** (живые игроки, сужение диапазонов);
- **кол-во денег в банке** (пот-оддсы каждого решения);
- линию раздачи (рейзы/коллы сужают моделируемый диапазон соперника);
- накопленную историю соперников (VPIP/PFR/fold-vs-bet), если платформа передала профили.

  измеренный CI; убраны мёртвый кэш стратегий и авто-создание мозгов каждую руку.
- 2026-11: направление зафиксировано — «лестница», гибридная схема GTO,
  локальность, модульность как требование №1; уволены идеи «авто-observe в
  decide» и «runtime-кэши» как нарушающие модульность.
- 2026-11: исправлен двойной учёт блайнда в сайзинге открытия (было 3.6bb
  вместо 2.6bb); внешний аудит стратегии (LLM) принят частично: исправлены
  инверсия слоуплея (рейз растёт с эквити), ширина защиты SB/BB (SB ~29%,
  BB ~52% против стила), пуш короткого стека (позиция+стек, без коллов),
  лимпы только за лимперами, изоляция лимперов, блеф против неизвестных
  (базовая частота), P(все фолд) произведением в мультипо.
- 2026-11: «глаза», этап 3 (карты) сдан — 100% против правды в headless
  (1–5 ботов), в полной матрице 52×17 слотов и на боевом пути (видимое окно,
  пиксели с экрана). Зафиксировано:
  - рантайм глаз — только пиксели экрана и реальный ввод; DOM, CDP-скриншоты
    и `/debug/state` — калибровке и тестам (`eyes/truth.py`)
    (граница с экрана снята 2026-11 — кадр отдаёт браузер, см. ниже);
  - стол детерминированной геометрии: целые позиции карт, постоянные слоты
    борда, места фиксированного размера, без теней на картах;
  - лица карт стола — растровые спрайты: рендер текста зависит от среды
    (headless ≠ видимое окно, видеокарта, шрифты машины), спрайт — нет;
  - зоны и шаблоны — одна калибровка, связаны `calibration_id`; шаблоны
    снимаются «по месту» с проверками детерминизма, а не предполагаются;
  - правда для тестов — замороженные состояния (ход героя / итог руки),
    сессии стола именуются (`?sid=`), вид уходит клиенту сразу после действия.
- 2026-11: «глаза», этап 4 (числа) сдан — 100% против правды в headless и на
  экране видимого окна. Способ выбран по замеру на 18 402 кропах нашего стола
  (11 шрифтов, оба режима): готовый распознаватель текста PP-OCRv5 через
  ONNX Runtime (rapidocr, модели в комплекте) — 99.98%, ~16 мс на зону,
  ~450 МБ; Tesseract 97.1%, EasyOCR ~34%. Пиксельные шаблоны знаков отменены:
  рендер текста зависит от шрифта и среды, то есть калибровка под каждый сайт.
  Зафиксирован принцип адаптации к любому руму:
  - картинки (карты) — шаблоны с самого сайта; текст — готовая модель;
    геометрия — зоны пресета; калибровка под сайт сводится к геометрии;
  - надписи действий («фолд/колл/чек») — необязательные подсказки: действия
    выводятся из изменений состояния, поэтому их отсутствие на сайте не мешает;
  - зона числа содержит только само число; «элемент скрыт» отличается от
    «числа есть» по фону зоны; формат сумм — настройка пресета;
  - суммы на нашем столе — в фиксированных полях (стек, колл, банк) и точные;
  - зеркало глаз («что видят глаза») — отдельный процесс, публикация только
    при открытом зрителе: отладка не может замедлить или уронить конвейер.
- 2026-11: глаза отвязаны от экрана — требование исследователя (окно стола
  нужно свободно таскать и убирать с глаз; привязка к месту на мониторе
  ошибочна: окно сдвинули или перекрыли — глаза читают чужие пиксели).
  Прежняя граница «рантайм — только пиксели экрана (mss)» пересмотрена по
  опытам на Chrome 139:
  - кадр отдаёт сам браузер (CDP): окно можно таскать, перекрывать другими
    окнами и уводить за край экрана; съём с монитора (mss) — запасной путь
    для страниц вне нашего браузера и проверка «как на экране» (`--screen`);
  - Selenium остаётся ради фиксированного вьюпорта (зоны пресета — точные
    пиксели), профиля с логином, реального ввода и кадров страницы без
    монитора;
  - команда снимка WebDriver не годится: поднимает перекрытое окно наверх и
    разворачивает свёрнутое, вдвое медленнее;
  - свёрнутое окно Chrome не рисует: глаза заранее видят, что страница
    скрыта (`WindowHidden`), не зависают, разворачивают окно и сообщают;
    без окна вовсе — `--headless`;
  - после реального клика курсор уходит с кнопки (`act.park`): под курсором
    кнопка подсвечена, и глаза не узнают её число. Приёмка —
    `scripts/test_window_states.py` (видимое / перекрытое / свёрнутое окно,
    реальные клики): 100%.

## 8. Известные упрощения уровня 1 (осознанный бэклог, не баги)

Equity-машина — эксплойтный уровень 1, а не равновесие. Осознанно НЕ
моделируется (переходит в уровень 2 — MCCFR-блюпринт, или в доработки):
- **блокеры** при выборе блефов;
- **адаптация частот/сайзингов к текстуре борда** (сухо/мокро — эквити учтено,
  частоты нет);
- **ICM** — проект моделирует кэш-игру (стеки сбрасываются); турнирный EV вне
  скоупа;
- **рейк** (сдвигает диапазоны, добавим параметром при необходимости);
- **IP/OOP постфлоп** — позиция учитывается только порядком ходов, без
  разных частот c-bet;
- **MDF-калибровка блефа на ривере** (блеф — от статистики оппонента, а не из
  безразличия; равновесную частоту даст блюпринт);
- **EV-сравнение пуша и колла** на коротком SPR (сейчас пороговое правило);
- джиттер порогов — шум для непредсказуемости, не теоретико-игровой микс.

# Pokafer: архитектура и как всё работает

Проект: покерный ИИ для исследований покерной математики и поведения людей.
Ядро идеи — **один контракт данных (Snapshot JSON)** между всеми частями:
движок, мозг, интерфейсы и инструменты обкатки говорят на одном языке,
поэтому всё стыкуется без переделок.

```
Источники состояния                    МОЗГ                     Потребители
─────────────────                 ──────────────              ──────────────
движок раздачи ─→ Snapshot JSON → валидация → легальные       → Decision JSON
веб-стол (живая игра) ─┘            действия → стратегия        → панель кнопок
глаза → трекер (настоящий стол) ─┘  (смешанная) → сэмпл         → графики/логи
исторические JSONL ─→ replay ─┘     + память об оппонентах      → анализ людей
                                                                   → пилот: клик актатора
```

## 1. core/schema.py — язык проекта

**Snapshot** — полное состояние раздачи С ТОЧКИ ЗРЕНИЯ одного игрока
(`actor_seat`): его карты (`hole_cards` только у `is_hero=True`), борд, банк,
стеки/вложения всех мест, вся история действий. Скрытая информация не
протекает: `engine.snapshot_for(seat)` показывает карты только этого места.

**Decision** — ответ мозга: действие (`fold/check/call/bet/raise`),
сумма «до», **distribution** — смешанная стратегия (вероятности действий),
пояснение и время.

Ключ действия — единый формат: `fold`, `check`, `call:2`, `bet:6`, `raise:12`.

## 2. core/cards.py — карты и комбинации

Карта = индекс 0..51 (`rank*4 + suit`), ранги 2..A. `evaluate7()` выбирает
лучшую пятёрку из 5–7 карт и возвращает сравнимый кортеж
`(категория, киккеры...)`; `hand_name_ru()` — «две пары: J и 3».

## 3. core/legal.py — что можно делать

Из Snapshot выводит: фолд (если есть ставка), чек/колл (колл укорачивается
до олл-ина), и **меню сайзингов** ставки/рейза: мин-рейз, ~½/¾/банк,
«рейз банком», олл-ин (всегда присутствует — отдельным элементом).
Мозг выбирает ТОЛЬКО из этого меню — нелегальных действий не бывает.

## 4. core/engine.py — движок раздачи (2–6 игроков)

`HandEngine(seat_stacks, names, button_seat, ...)`:
- раздаёт карты, ставит блайнды (HU: кнопка = SB, ходит первой префлоп;
  3+ — первый после BB), ведёт круги ставок по улицам;
- раунд закрыт, когда все не-олл-ин активные походили и ставки равны;
  повышение сбрасывает счётчик «кто уже ответил»;
- олл-ины: недокрытая часть последней ставки ВОЗВРАЩАЕТСЯ
  (`_refund_uncalled`), банк делится на слои (`_side_pots`), сплиты —
  целыми центами, остаток цента первому победителю;
- итог (`result`): победители, банки по слоям, выигрыши, вскрывшиеся карты;
  `bet_street/invested` обнуляются (иначе двойной счёт — ловится
  инвариантом бенчмарка).

## 5. brain — как принимается решение

`Brain.decide(snap, profiles=None, allowed=None)` (pokafer/brain/api.py):
1. `legal_actions(snap)` — меню;
2. `strategy.distribution(snap, legal, profiles)` — **смешанная стратегия**:
   вероятности по действиям (здесь живёт непредсказуемость и блеф);
3. `allowed` — типы действий, которые платформа может исполнить (пилот
   запрещает рейзы, когда история раздачи восстановлена неточно): вес
   остальных отбрасывается, остаток перенормировывается; не осталось ничего —
   чек или колл;
4. сэмплирование действия из распределения;
5. `Decision` + пояснение.

**Мозг чистый** (docs/DECISIONS.md §5): ничего не парсит, не хранит, не
пишет; профили оппонентов приходят аргументом, а если платформа инъецировала
память (`memory=`) и профили не переданы явно — читаются из неё. Собирает
статистику платформа (`observe()`), не мозг.

Стратегии — подключаемые модули (pokafer/brain/strategies/):
- `base.Strategy` — интерфейс: `distribution(snap, legal, profiles)`;
- `random` — равномерно (калибровка);
- `heuristic` — недо-GTO: сила руки (формула Чена префлоп / категория+дро
  постфлоп), пот-оддсы, рандомизированные блефы. Все пороги — в словаре
  `PARAMS`;
- `micro` — наследник heuristic: только переопределяет PARAMS (блеф почти
  выключен, тонкий велью, крупнее сайзинги) — эксплойт под микролимиты;
- `fish` — синтетическая «рыба» (лузово-пассивная модель популяции NL2–10);
- **`equity` — уровень 1: решения из вычисленных вероятностей**
  (strategies/equity.py):
  - Монте-Карло-эквити против моделируемого диапазона каждого живого
    оппонента (на ривере с одним оппонентом — точный перебор);
  - колл — по пот-оддсам с маржой; велью — по эквити; сайзинги — от эквити
    и SPR (стек/банк); блефы — от fold-vs-бет статистики соперников;
  - префлоп — percentile руки (169 классов) против диапазонов по позиции,
    защита блайндов против стила, пуши на коротких стеках.

Модель диапазонов — `pokafer/brain/ranges.py`: чистая функция
(snapshot + профили) → сэмплер рук оппонента (позиция, линия раздачи,
стек в bb, VPIP); число игроков берёт из Snapshot.

Реестр: `strategies/__init__.py` (`register/available/get`). **Добавить
стратегию = один файл с классом + одна строка регистрации** — она сразу
доступна в CLI, столе, бенчмарке.

`memory.py` — платформенная память: снапшоты → профили (VPIP/PFR/AF/
фолд-vs-бет) через `analysis/opponent_stats.py`, кэш до новых данных.

## 6. Интерфейсы

**HTTP-API мозга** (`brain/service.py`): stateless, `POST /v1/decide`
принимает снапшот, возвращает Decision; `/v1/schema` — JSON-схема;
`/v1/strategies` — список. Доля миллисекунды на решение.

**Веб-стол** (`web/table_server.py` + `static/`): человек (место 1) против
до 5 ботов, у каждого своя стратегия (меняется на лету сообщением
`configure`). Протокол WebSocket: сервер шлёт `view` (вид стола с
перспективы героя), `bot` (ход бота с его распределением), `result`
(итог; карты шоудауна не прячутся до следующей руки); клиент — `action`,
`new_hand`, `configure`, `hint`. Боты ходят с паузой 0.5 с; следующая
рука — только по кнопке. Клиент — vanilla JS без сборки: стол, слайдер
рейза с пресетами, лог с распределениями, кнопки всегда видны (недоступные
— серые). Стол — ещё и полигон глаз: детерминированная геометрия (целые
позиции, карты-спрайты, диск дилера в своём слоте), правда для тестов
(`GET /debug/state?sid=` — вид героя, `GET /debug/hand?sid=` — раздача с
историей действий движка; рантайм глаз их не читает) и воспроизводимая
колода при заданном зерне сессии (`TableSession(seed=…)`).

**CLI** (`cli.py`): `pokafer` без аргументов — список команд; каждая
подкоманда пробрасывает флаги в свой скрипт (справка: `pokafer X -h`);
`pokafer status` — что запущено, стратегии, последние прогоны.

## 7. Инструменты обкатки

**benchmark** (`pokafer/benchmark.py`, конфиг `configs/benchmark.py`):
рассадка «место → стратегия» (кнопка равномерно по кругу — позиционного
смещения нет), свежие стеки на каждую раздачу, тысячи раздач быстро
(~440 рук/с на 9-max), итог — bb/100 на место ± 95% CI и HTML-отчёт с
графиком суммарного банка каждой стратегии.

Главное — **инвариант целостности**: после КАЖДОГО действия проверяется,
что Σ(стеки+вложения) не изменилась и стеки не отрицательны. Нарушение —
аварийный дамп раздачи (действия + сид колоды) в `data/logs/` и останов.
Именно он поймал два реальных бага движка (двойной счёт invested после
раздачи; утечку цента в сплит-потах 7/3).

История прогонов копится в `data/logs/results.jsonl` (для статьи).

**arena** — дуэль 1-на-1 двух стратегий (bb/100, CI).
**replay** — прогон мозга по историческим JSONL-снапшотам + профили игроков.

## 8. Как сделать типовые вещи

Добавить стратегию:
1. файл `pokafer/brain/strategies/my.py` с классом (наследуй `HeuristicStrategy`
   и переопредели `PARAMS`, либо пиши свой `distribution`);
2. зарегистрировать в `strategies/__init__.py`;
3. `pytest`; использовать: `pokafer demo --strategy my`, вписать в
   `configs/benchmark.py` или чип бота на столе.

Обкатать: отредактировать `configs/benchmark.py` → `pokafer bench`.
Отчёт: `data/logs/benchmark_*.html` (график + таблица).

## 9. Честные ограничения и долги

- дубли в UI-слое: перевод действий (`human_action` в demo_cli ≈
  `_ru_action` в table_server ≈ `action_ru` в eyes/report.py), константы
  HERO/NAMES/STREET_RU — при правках трогать все места;
- подсказка комбинации в браузере (JS) грубее, чем `evaluate7` в CLI;
- анте не реализовано (поле в схеме есть);
- парсер PokerNow — заготовка, ждёт реальный экспорт в `data/raw/`;
- equity-стратегия — уровень 1: эквити статично (нет планирования будущих
  улиц), диапазоны — параметрическая модель, а не клоны игроков;
  калибровка под реальных людей — после PokerNow-адаптера;
- equity медленнее эвристик (MC на решение): 9-max бенчмарк с equity-местами
  ~12 рук/с против ~440 у эвристик; PARAMS["rollouts"] — ручка компромисса.

## 10. Тесты

`pytest -q` — 211 штук: JSON-контракт туда-обратно, легальность действий,
сохранение чипов (стресс 300 раздач до цента, сайд-поты), WebSocket-протокол
стола, инварианты бенчмарка, глаза без браузера (83: пресеты, читатель карт,
чисел — в том числе настоящая модель на кадре «0» стека олл-ина, индикаторы,
память чтения, цикл, актатор, закрытие браузера), трекер без браузера (33:
движок стола играет, кадры пропадают, раздача обязана восстановиться) и
пилот без браузера (16: кнопки — вызов движка, клики теряются), плюс
фундамент уровня 1: эквивалентность
evaluate7_fast/evaluate7, эквити против эталонных чисел (AA 0.852 и др.),
точный ривер, ранжирование 169 классов, сужение диапазонов линией и
профилями, легальность и детерминизм equity-стратегии, позиция префлоп
(шкала кончается кнопкой: кнопка открывает шире всех, её рейз — стил).

## 11. Глаза, трекер и бой: живой стол → Snapshot → клик

`pokafer/eyes/` — единственный канал, которым мозг видит настоящий стол.
Подробно — [EYES_GUIDE.md](EYES_GUIDE.md); здесь — место в архитектуре.

- **Глаза** читают только пиксели кадра, который отдаёт браузер (DOM и
  адреса правды — калибровке и тестам). Читатели общие для любого рума;
  от рума зависит пресет: зоны, шаблоны карт, фон и формат чисел, кнопки,
  два вида индикаторов (чей ход, дилер, «рука окончена»), порядок мест.
- **Трекер** — чистая логика между глазами и мозгом: подтверждает состояние
  двумя одинаковыми кадрами, берёт уровень прямо из кадра (стеки, ставки,
  банк, борд), а действия между состояниями восстанавливает поиском по
  правилам покера — спрашивая `legal_actions`, а не дублируя правила.
  Единственное объяснение — точно; нет или несколько — честный пропуск.
  Места нумеруются по часовой стрелке от героя (герой — 1), как у движка.
- **Snapshot** всегда с точки зрения героя (`actor_seat = 1`): тот же
  контракт, что от движка и replay, поэтому мозг, память об оппонентах и
  анализ работают с живого стола без переделок.
- Приёмка против движка: уровень — ни одного расхождения, история —
  действие в действие (обычный темп) или помеченный пропуск (быстрый).
- **Пилот** (`eyes/pilot.py`) — бой (`pokafer fight`): одно решение на
  подтверждённое состояние (мозг → актатор); клик обязан сработать — трекер
  находит действие героя в восстановленной истории, иначе клик повторяется
  тем же решением (не более трёх раз, затем стоп); по неполной истории —
  только фолд/чек/колл. Пилот — тоже чистая логика: актатор для него любой
  объект с методами действий.
- `Tracker.serial` растёт только на новом состоянии — по нему пилот отличает
  «то же состояние» от «стол изменился»; `Tracker.changing` — отличие видно,
  но ещё не подтверждено.
- Приёмка боя (`scripts/test_fight_accuracy.py`): срез, меню легальных
  действий на каждом решении и каждый клик — против движка; на обычном темпе
  стола во всех прогонах расхождений нет.

## 12. Фундамент GTO (уровень 2, готовится)

Общие модули для блюпринта уже есть (docs/DECISIONS.md §2):
- `core/abstraction.py` — 169 префлоп-классов, аналитический бакет силы
  руки (калиброван на MC-эквити), бакеты стеков, ключи информационных
  множеств, абстрактные размеры ставок + маппинг в легальные;
- `core/data/preflop_equity.json` — генерируемый артефакт ранжирования
  (`scripts/gen_preflop_equity.py`, seed фиксирован, коммитится);
- `core/equity.py` — MC-эквити и точный ривер для калибровки абстракции.
Дальше: MCCFR-тренер (`pokafer/cfr/`, external sampling, N игроков) →
артефакт блюпринта → стратегия `gto_blueprint` = чтение таблицы.
